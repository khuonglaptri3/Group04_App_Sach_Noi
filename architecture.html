1. Tổng Quan Project

Project là ứng dụng Android cho phép người dùng đọc ebook và nghe audiobook. Ứng dụng có các chức năng chính: đăng ký, đăng nhập, xem trang chủ, tìm kiếm sách, xem chi tiết sách, đọc ebook, nghe audio, đánh dấu trang, highlight, ghi chú, đánh giá sách, tải sách về máy, quản lý thư viện và thông tin cá nhân.

Chức năng người dùng

  • Đăng ký, đăng nhập, lưu phiên đăng nhập bằng token.
  • Xem sách audio, ebook, danh mục, sách liên quan.
  • Đọc EPUB, phân trang, bookmark, highlight, ghi chú.
  • Nghe audiobook, tua, đổi chương, hẹn giờ ngủ, đổi tốc độ.
  • Viết review, xem review, quản lý premium và bảo mật.
  • Tải file audio/ebook về bộ nhớ riêng của ứng dụng.

Công nghệ chính

  • Java, AndroidX, AppCompat, Material Components.
  • OkHttp để gọi Supabase API.
  • Glide để tải ảnh từ URL.
  • MediaPlayer, MediaSession, Foreground Service để phát audio nền.
  • Room, LiveData, ViewModel để cache dữ liệu local.
  • WorkManager để chạy đồng bộ nền định kỳ.

6. 4 Core Components (Thành Phần Cốt Lõi) Của Android

Dự án vận dụng linh hoạt cả 4 thành phần cốt lõi của hệ điều hành Android (4 Android Core Components), tạo nên một hệ thống phần mềm hoàn chỉnh, tối ưu và đạt chuẩn kỹ thuật Android cao nhất.

6.1 Permissions (Quyền ứng dụng)

  • INTERNET: gọi Supabase API và tải ảnh/file.
  • POST_NOTIFICATIONS: hiện notification phát audio và tải file trên Android 13+.
  • FOREGROUND_SERVICE & FOREGROUND_SERVICE_MEDIA_PLAYBACK: cho phép chạy service phát nhạc ngầm.
  • BIND_QUICK_SETTINGS_TILE: cấp quyền cho TileService hiển thị nút bấm trên thanh trạng thái.

6.3 Service (Thành phần Chạy ngầm)

Định nghĩa: Service là thành phần chạy ẩn dưới nền để thực hiện các tác vụ kéo dài mà không cần giao diện người dùng (UI).

  • AudioPlayerService (Foreground Service): Dịch vụ quan trọng nhất dùng cho media playback. Giúp ứng dụng tiếp tục phát nhạc và hiển thị thanh điều khiển trên màn hình khóa.
  • SyncWorker (WorkManager): Dịch vụ đồng bộ dữ liệu ngầm kiểu mới của Google. Tự động thức dậy mỗi 12 tiếng để đồng bộ dữ liệu offline từ Room DB lên đám mây Supabase.
  • QuickPlayTileService (Tile Service): Tạo nút "Tiếp tục nghe" trên thanh trạng thái (Quick Settings). Nhấn vào là có thể tiếp tục nghe sách ngay lập tức kể cả khi ứng dụng đang tắt hoàn toàn.
  • CleanupService (Background Service): Chạy ngầm mỗi khi mở app để tự động quét và dọn dẹp các tệp tin tạm (Cache), tự động stopSelf() sau khi xong.

6.4 BroadcastReceiver (Thành phần Lắng nghe Sự kiện)

Định nghĩa: BroadcastReceiver cho phép ứng dụng đăng ký lắng nghe các "thông báo/sự kiện hệ thống" từ hệ điều hành hoặc từ các ứng dụng khác.

  • AudioBecomingNoisyReceiver: Liên tục lắng nghe phần cứng. Nếu người dùng đang nghe sách nói bằng tai nghe mà đột ngột rút tai nghe ra, hệ điều hành sẽ phát ra tia Broadcast (ACTION_AUDIO_BECOMING_NOISY). Ứng dụng bắt tín hiệu này và lập tức tạm dừng phát nhạc.
  • MediaButtonReceiver: Lắng nghe sự kiện người dùng bấm vào các nút vật lý trên tai nghe Bluetooth (nút Play/Pause) để điều khiển ứng dụng từ xa.

6.5 Content Provider (Thành phần Cung cấp/Chia sẻ Dữ liệu)

Định nghĩa: Content Provider quản lý quyền truy cập vào dữ liệu trung tâm, cho phép ứng dụng này chia sẻ an toàn dữ liệu của mình cho ứng dụng khác.

  • FileProvider: Lớp con mạnh mẽ nhất của Content Provider do AndroidX cung cấp. Khai báo androidx.core.content.FileProvider với authority ${applicationId}.fileprovider.
  • File res/xml/file_paths.xml cho phép cấp URI an toàn (content://) cho file trong thư mục hệ thống Download/.
  • Nhờ đó, ứng dụng có thể chia sẻ an toàn file .epub hoặc .mp3 cho ứng dụng đọc sách bên thứ ba mà không bị dính lỗi bảo mật FileUriExposedException.

7. Lưu Trữ Dữ Liệu

Supabase

  • Backend chính của ứng dụng.
  • Auth API cho đăng ký, đăng nhập, refresh token.
  • REST API cho books, profiles, reviews, bookmarks, progress, library.
  • Storage API cho avatar trong bucket avatars.
  • RPC cho search, review, favorite, notifications và xóa tài khoản.

SharedPreferences

  • Quản lý bằng SessionManager.
  • Tên preferences: UserSession.
  • Lưu userId, userName, accessToken, refreshToken.
  • Hàm clear() dùng khi logout hoặc hết phiên.

Room Database

  • Database name: app_database.
  • Entity: BookEntity.
  • Table: books.
  • DAO: BookDao.
  • Dùng để cache sách featured và trả dữ liệu nhanh/offline.

File Local

  • DownloadHelper dùng DownloadManager.
  • File audio lưu dạng {bookId}_audio.mp3.
  • File ebook lưu dạng {bookId}_ebook.epub.
  • Nơi lưu: app-specific external storage, thư mục Download.

10. Main Thread Và Background

Android có main thread để xử lý UI. Mọi thao tác cập nhật giao diện như set text, hiện Toast, cập nhật RecyclerView, SeekBar cần thực hiện trên main thread.

Loại xử lý Ví dụ trong project Ghi chú
Main thread onCreate(), onResume(), click listener, cập nhật UI Không nên làm việc nặng trên main thread.
OkHttp background client.newCall(request).enqueue(...) Gọi API bất đồng bộ, callback không luôn ở main thread.
UI callback runOnUiThread(...) Dùng để quay về main thread khi cần cập nhật UI.
Media async MediaPlayer.prepareAsync() Chuẩn bị audio bất đồng bộ, không block UI.
Thread thủ công EpubExtractor, EbookReaderActivity.paginationThread, upload avatar Xử lý tác vụ nặng: tải, giải nén, phân trang, upload.
ExecutorService BookRepository Ghi Room database ở background.
WorkManager SyncWorker Task nền định kỳ, có constraint network.
DownloadManager DownloadHelper Hệ thống Android xử lý download nền.

Điểm cần giải thích khi báo cáo: Service không đồng nghĩa với background thread. Service là Android component có vòng đời riêng. Các hàm lifecycle của Service vẫn có thể chạy trên main thread. Tác vụ nặng trong Service vẫn nên đưa sang thread/worker riêng.

12. Nội Dung Nên Trình Bày Khi Báo Cáo

Mô tả ngắn gọn

Ứng dụng App Sách Nói là ứng dụng Android hỗ trợ người dùng đọc ebook và nghe audiobook. Hệ thống dùng Supabase làm backend, OkHttp để giao tiếp API, Glide để tải ảnh, Room để cache dữ liệu local, MediaPlayer kết hợp Foreground Service để phát audio nền, DownloadManager để tải file và WorkManager để thực hiện đồng bộ nền định kỳ.

Điểm nhấn kỹ thuật

  • Đã chia package theo nhóm chức năng: model, view, controller, service, data, repository, helper.
  • Audio playback dùng MediaPlayer và AudioPlayerService để nghe tiếp khi thoát màn hình.
  • Session được lưu bằng SharedPreferences và có cơ chế refresh token.
  • Dữ liệu featured book có cache local bằng Room và quan sát bằng LiveData.
  • Gọi API bất đồng bộ bằng OkHttp.enqueue(), cập nhật UI bằng runOnUiThread().
  • File download được lưu trong app-specific external storage và mở bằng FileProvider.

Kết luận kiến trúc

Project có kiến trúc MVC là chính: Model chứa dữ liệu, View gồm Activity/Fragment/XML/Adapter, Controller xử lý sự kiện và logic. Ngoài ra project có bổ sung các thành phần hiện đại của Android như Repository, ViewModel, LiveData, Room và WorkManager để tăng khả năng mở rộng, cache dữ liệu và xử lý nền.

Hạn chế có thể nêu trong báo cáo

  • Một số Activity/Fragment vẫn gọi Supabase trực tiếp, chưa đưa hết qua Repository.
  • Một số chuỗi/comment tiếng Việt trong code có dấu hiệu lỗi encoding, nên sửa để code sạch hơn.
  • SyncWorker hiện mới mô phỏng đồng bộ, có thể phát triển thêm để đồng bộ progress/offline data thật.
  • Nếu muốn kiến trúc rõ hơn nữa, có thể chuyển dần sang MVVM đầy đủ: UI -> ViewModel -> Repository -> Local/Remote.
